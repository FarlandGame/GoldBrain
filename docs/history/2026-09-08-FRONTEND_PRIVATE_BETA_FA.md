# تحویل Frontend نسخه خصوصی GoldBrain

این نسخه با تغییرات Backend شاخه `backend/iranian-market-providers` تا commit
`08ad208` هماهنگ شده است. کد Backend از شاخه همکار ادغام شده؛ پیاده‌سازی این کار
در Frontend، تست‌های کلاینت، مستندات مشترک و اسکریپت اجرای ویندوز است.

## وضعیت قابلیت‌ها

| بخش | رفتار نسخه تحویلی |
| --- | --- |
| Dashboard، Markets، Watchlist | فقط GOLD18، USDT، BTC؛ خواندن snapshot ذخیره‌شده، منبع، زمان، وضعیت کهنگی، نمودار واقعی و پیش‌بینی ثبت‌شده |
| جزئیات دارایی | صفحه مشترک، افق مجاز هر دارایی، نمودار، ثبت پیش‌بینی، دلایل، تحلیل عمیق، سناریوها، اخبار و عملکرد |
| Auth | ثبت‌نام، ورود، تمدید چرخشی توکن، بازیابی نشست، خروج، درخواست و تأیید بازیابی رمز |
| توکن | Refresh در Secure Storage سیستم‌عامل و وابسته به نشانی Backend؛ Access فقط حافظه؛ بدون کلید مالک/Provider در ساخت کاربر |
| Forecast | خواندن latest با symbol/horizon/timeframe صریح، نمایش ID و زمان هدف و دلایل تصمیم و جزئیات مدل |
| No Trade | تصمیم سرور، اعتبار ارزیابی، خطای داده، کهنگی و انقضای پیش‌بینی رعایت می‌شود؛ امتیاز provisional به اطمینان معاملاتی بالا تبدیل نمی‌شود |
| Performance | انتخاب دارایی/افق، تعداد کل و مستقل، MAE، MAPE، دقت جهت، پوشش بازه، Brier و وضعیت Calibration |
| Signals | سه دارایی، فیلتر دارایی، افق یک ساعت، تصمیم سرور و مسیر بررسی جزئیات |
| News / Deep Analysis | فقط API سرور، منابع و زمان خبر، گزارش ساختاریافته؛ بدون فراخوانی مستقیم AI از مسیر محصول |
| Paper Trading | ساخت حساب فرضی، خرید/فروش دستی، موجودی، موقعیت، ژورنال، کارمزد و سودوزیان؛ ارسال مجدد خودکار سفارش پس از Timeout انجام نمی‌شود |
| Alerts | ساخت، حذف، فهرست و ارزیابی هشدار؛ بررسی دوره‌ای هنگام فعال بودن برنامه |
| Sessions / Profile | اطلاعات auth/me، نشست‌های دستگاه‌ها و لغو آن‌ها؛ وضعیت MFA و تأیید ایمیل |
| Settings | زبان فارسی/انگلیسی، تم، مشخص بودن تنظیمات محلی؛ دیده‌بان و توقف محلی معاملات وابسته به کاربر |
| خطا / اندازه | حالت خالی، قطع ارتباط، خطای Provider، پاسخ ناقص، Stale و No Signal؛ ناوبری پنجره باریک و RTL |

اسکرین‌های Legacy حفظ شده‌اند، اما entrypoint برنامه به آن‌ها مسیر ندارد.
موتور پیش‌بینی محلی، Supabase و Providerهای مستقیم در مسیر فعال محصول نیستند.
تغییر درصدی ناموجود با عدد محاسبه‌شده یا صفر جایگزین نمی‌شود. نمودار نقطه گمشده
را پر نمی‌کند. داده مصنوعی فقط در `frontend/test/` وجود دارد.

## اجرای نسخه محلی

1. در ریشه پروژه `Start-PrivateBeta.bat` را اجرا کنید.
2. API روی `127.0.0.1:8000` و worker جمع‌آوری داده اجرا می‌شوند و برنامه باز می‌شود.
3. حساب جدید GoldBrain بسازید؛ حساب Supabase قدیمی خودکار منتقل نمی‌شود.
4. پس از پایان، `Stop-PrivateBeta.bat` را اجرا کنید.

اسکریپت قبل از migration از فایل پیش‌فرض `backend/data/goldbrain.db` نسخه پشتیبان
در `.goldbrain/` می‌گیرد. برای Database سفارشی باید روش Backup همان محیط استفاده
شود. لاگ‌های API و worker نیز در `.goldbrain/` هستند و وارد Git نمی‌شوند.
اگر پورت ۸۰۰۰ اشغال باشد، اسکریپت سرویس دیگری را متوقف نمی‌کند.
تنظیمات و Secrets Backend در `backend/.env` می‌مانند.

در نصب تازه، خالی بودن تاریخچه و «بدون سیگنال» طبیعی است: worker داده واقعی را
جمع می‌کند. GOLD18 حداقل به ۲۴ کندل ساعتی واقعی نیاز دارد. صفحه هر دقیقه
snapshot را می‌خواند و خودش Forecast تازه تولید نمی‌کند. دکمه ثبت پیش‌بینی
در جزئیات، درخواست صریح کاربر است. worker فعلی پیش‌بینی یک‌ساعته را تولید می‌کند؛
افق‌های دیگر با درخواست کاربر و فقط در صورت کفایت داده تولید می‌شوند.

افق ۱۵ دقیقه BTC/USDT از کندل یک‌دقیقه‌ای سرور استفاده می‌کند؛ سایر افق‌ها از
کندل یک‌ساعته. افق ۴ ساعت تتر و یک هفته طلا تا تأیید کفایت داده فعال نیستند.
«۲۴ ساعت آینده» پایان روز تقویمی نیست.

## تست دستی پیشنهادی

- ورود/ثبت‌نام، بستن و بازکردن برنامه برای بازیابی نشست، مشاهده پروفایل، خروج.
- بررسی هر سه دارایی، زمان و واحد قیمت، جزئیات و تغییر افق؛ ثبت پیش‌بینی در صورت وجود تاریخچه کافی.
- Performance و دلایل No Trade؛ نبود نمونه نباید دقت بالا ایجاد کند.
- خبر و تحلیل عمیق؛ خطای Provider یا داده ناکافی باید قابل مشاهده باشد.
- ساخت حساب فرضی با ارز متناسب، سفارش کوچک، بررسی کارمزد و ژورنال و فروش موقعیت.
- ساخت هشدار، مشاهده نشست و لغو آن؛ بررسی پنجره باریک و تغییر زبان.
- قطع Backend: قیمت ذخیره‌شده باید خطادار/قدیمی بماند؛ سفارش نباید با داده قدیمی ارسال شود.

## محدودیت‌های واقعی

این تحویل پایان همه معیارهای محصول نیست. ریسک خودکار، Slippage، حد ضرر/سود و
Kill Switch سراسری هنوز API اجرایی ندارند. توقف داخل برنامه فقط ارسال سفارش
از همین دستگاه را متوقف می‌کند و صریحاً با همین عنوان نمایش داده می‌شود.
ربات خودکار و معامله واقعی پیاده‌سازی نشده‌اند. جزئیات قابل تحویل به Backend
در `FRONTEND_API_GAPS.md` ثبت شده‌اند.

تست اتصال از کلاینت Flutter به FastAPI واقعی با Database موقت و Providerهای
مصنوعی انجام می‌شود؛ این تست کیفیت داده بازار زنده یا سودآوری مدل را تأیید نمی‌کند.
تصاویر پوشه `screenshots/private-beta/` نیز شواهد UI با داده تست هستند.
