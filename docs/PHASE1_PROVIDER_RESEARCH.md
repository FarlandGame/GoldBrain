Every paid subscription is deferred until all eight phases are ready for daily use. Prices and terms must be checked again at that point.

There is no verified single provider that both prices Iranian-market GOLD18/EUR and supplies every top-20 coin, including XMR and LEO, with 30 days of comparable OHLC at a proven live cadence. The Phase 1 architecture keeps source, timestamp, unit and currency explicit. Wallex public API supplied 19 of 20 tracked crypto quotes and 30-day hourly OHLC during the real probe; it omits a per-asset quote timestamp, so receipt time is never presented as source time. [CoinGecko public/demo](https://www.coingecko.com/en/api/pricing) supplied the remaining LEO USD quote and historical *price samples*, which are not OHLC. Navasan is the preferred domestic gold/FX integration, while Wallex remains primary for listed crypto. ZARIX is a reachable experimental aggregator used only as a visibly unverified global reference; it is not an established verified company or trusted domestic-price source. PersianToolbox's generic gold-per-gram field is not Iranian 18K gold and has been removed as a GOLD18 fallback. None of these arrangements proves complete domestic history or continuous minute-fresh quotes. Commercial-use permission and required attribution remain to be reviewed before launch.

Navasan's nonrenewable three-month free access is a short window: activate it only when a real API verification run is ready, then retain source-labelled recorded responses for repeatable offline tests. Do not present mocked responses as market observations. The free tier's two-hour update cadence means a technically successful call may still return a stale quote and must be labelled or rejected accordingly.

## 2026-09-26 verification of previously suggested public fallbacks

- **ZARIX:** The [website](https://zarix.online/), [developer documentation](https://zarix.online/developers/), and [currencies JSON endpoint](https://zarix.online/api/?endpoint=markets&category=currencies&page=1&limit=100) all responded on 2026-09-26. The documentation calls it a public experimental version. The observed USD/EUR rows had `sourceTime: null`; `updatedAt` is an aggregator update, not proof of an underlying market observation. No independent operating-company identity or service guarantee was verified. It is a reachable experimental aggregator, **not a verified domestic USD/EUR source**.
- **PersianToolbox:** The [website](https://persiantoolbox.ir/), [market API documentation](https://persiantoolbox.ir/developers/api/market), [live endpoint](https://persiantoolbox.ir/api/market), [operator page](https://persiantoolbox.ir/about), and [public source code](https://github.com/alirezasafaei-dev/persiantoolbox/blob/main/app/api/market/route.ts) are real and reachable. The operator identifies himself as an individual developer; no established market-data company or service guarantee was independently verified. The docs expressly say the numbers are technical reference rates, not guaranteed Iranian free-market or tradable prices. The gold code computes tokenized global gold per gram using an FX rate, with no 18K purity or Iranian transaction data. Its response timestamp is not the upstream gold timestamp. **This endpoint does not provide GOLD18.**

There is still **no confirmed free, minute-fresh, tradable Iranian-market source for USD, EUR, or GOLD18** in this build. Navasan remains a keyed candidate, but no key has been supplied and its free-plan refresh cadence is too slow for the live requirement. Do not activate a paid subscription during development.

## 2026-09-26 authenticated Navasan verification

The user configured a development key in an ignored local Backend `.env`. The key was never copied into this document or committed. Real HTTPS requests to `https://api.navasan.tech` returned the following observations; they supersede the earlier **no key/no authenticated response** statements above. The sample is evidence of API coverage at this time, not an uptime or price-accuracy guarantee.

| Symbol | `/latest/` value at the sample | Provider timestamp (UTC) | Backend receipt (UTC) | `/ohlcSearch/` (35-day request) | `/dailyCurrency/` with Jalali date |
|---|---:|---|---|---|---|
| `usd_sell` (USD, Tehran sell) | 234,000 | 2026-09-26 17:31:55 | 2026-09-26 18:40:37 | HTTP 200, 35 daily rows, 34 completed days | HTTP 200, 61 updates on 1405-07-04 and 20 on 1405-07-03 |
| `eur` (EUR) | 266,540 | 2026-09-26 17:31:55 | 2026-09-26 18:40:37 | HTTP 200, 35 daily rows, 34 completed days | HTTP 422 `Invalid parameter values` for both dates |
| `18ayar` (18K gold, gram) | 23,858,440 | 2026-09-26 18:40:13 | 2026-09-26 18:40:37 | HTTP 200, 35 daily rows, 34 completed days | HTTP 200, 131 updates on 1405-07-04 and 144 on 1405-07-03 |

The first daily OHLC row was 1405-06-01 and the last was 1405-07-04 for all three symbols. The last row was the **still-open current Tehran day** and must not be treated as a completed candle. Thus the provider returned enough completed daily OHLC for 7-day and 30-day views; the existing Backend parser excluded the open row during a real adapter call. The standard Flutter 24-hour path asks the Backend for hourly candles, while its Navasan read-through currently supplies only daily OHLC. Navasan has real intraday **price updates**, not documented hourly OHLC, for USD and GOLD18; the current app route does not yet expose them as a truthful 24-hour chart. EUR's intraday endpoint rejected the verified request, so a provider-backed EUR 24-hour view is **not confirmed**. USD updates observed on 1405-07-04 began at 11:17 Tehran and ended at 20:59, leaving an overnight/nontrading gap inside a 24-hour view. Do not fill that gap with invented prices.

Navasan's JSON omitted `currency` and `unit` for both latest quotes and history. Its [Persian API guide](https://www.navasan.tech/webserviceguide/) defines `usd_sell` as Tehran USD sell and `18ayar` as gold per gram. The [Navasan market site](https://www.navasan.net/) labels the corresponding cash-FX and gold tables **Toman**, while its [English API page](https://www.navasan.tech/en/api/) generically says **IRR**. Independent [TGJU USD](https://gem.tgju.org/profile/price_dollar_rl), [EUR](https://gem.tgju.org/profile/price_eur/history), and [18K gold](https://gem.tgju.org/profile/geram18/history) archives explicitly use Rial and show values about ten times Navasan's numerical values for nearby dates. The operational interpretation for these three symbols is therefore **Toman (IRT) per currency unit or per gram**, but the API's lack of an explicit field and contradictory English copy remain a contract risk. GoldBrain retains `unit_from_provider_catalog`/`UNVERIFIED` rather than silently claiming the response itself proves the unit.

The real Backend adapter returned USD/EUR as `STALE` at roughly 69 minutes of source age and GOLD18 as age-fresh `LIVE` at 24 seconds; all retained `UNVERIFIED` quality. These freshness words describe the **age of a particular provider timestamp**, not guaranteed service cadence. Navasan's [published free plan](https://www.navasan.tech/api/) permits 120 calls/month and advertises updates every two hours, valid for three months. A single short observation cannot establish the actual plan's sustained update interval, and the free feed must be labelled **not real-time** in the UI even when one quote has a recent source timestamp. Its free-plan page says nonrenewable in Persian and renewable in English; confirm with the vendor before depending on access beyond the trial. No paid plan was purchased; committed API cost remains 0 Toman.

### Same-time official-widget check and EUR endpoint correction

The earlier operational Toman inference is now confirmed at the **symbol level**: at 2026-09-26 19:02:52 UTC, an authenticated Navasan `/latest/` response and Navasan's own [public widget](https://www.navasan.tech/wp-navasan.php?usd&eur&18ayar) returned identical numbers for all three symbols: USD 234000, EUR 266540 and 18K gold/gram 23858440. The widget's column header is explicitly `قیمت (تومان)`; [Navasan's widget page](https://www.navasan.tech/module.php) embeds this endpoint. For these symbols the API's raw prices are already **Toman**, so dividing them by ten would be wrong. The generic English API-page mention of IRR is contradicted by this exact official widget/API comparison. The JSON still lacks an explicit unit field, so the code records the provider-specific conversion rule and source identity rather than inferring from magnitude. The widget's gold clock did not match the API timestamp; only the authenticated API timestamp is used for freshness.

The real EUR `/dailyCurrency/` 422 was independently reproduced for `eur` on two Jalali dates and for `eur_hav` and `mex_eur_sell`; the same key and date returned HTTP 200 and 61 USD samples. This is an unsupported **item at that endpoint**, not a bad key or date. The [Navasan API guide](https://www.navasan.tech/webserviceguide/) lists a narrower item set under `/dailyCurrency/` and omits EUR, while EUR does appear in the daily OHLC symbol list. GoldBrain must stop sending EUR intraday requests there. A future EUR 24-hour view can use only its own persisted, source-timestamped Navasan `/latest/` observations and must disclose sparse/insufficient coverage. Navasan offers no verified documented intraday EUR backfill for this key.

### 2026-09-27 — Implemented 24-hour samples and live recheck

The Backend now exposes `/api/v1/market/{asset}/samples?range=24h` as observed **price samples**, not OHLC. Its Navasan `/dailyCurrency/` calls are restricted to `USD` and `GOLD18`. In a new authenticated live probe on 2026-09-27, the integrated adapter returned **60 USD** and **143 GOLD18** distinct source-timestamped observations inside the requested 24-hour window, both in canonical `IRT` with `VALID` unit quality after normalization. The sample ranges were 07:16:42–17:29:04 UTC for USD and 2026-09-26 18:40:13–2026-09-27 18:30:13 UTC for GOLD18; gaps remain gaps. A separate real `/latest/` adapter probe returned USD 235200, EUR 267910 and GOLD18 24020040, all `IRT`/`VALID` with API provider timestamps. These are point-in-time success checks, not sustained reliability or minute-freshness guarantees.

The same endpoint serves `EUR` only from Navasan `/latest/` observations already persisted with their provider timestamps. It never calls EUR `/dailyCurrency/`, so the verified upstream 422 is avoided. Until two distinct EUR source observations are present in the last 24 hours, the app reports insufficient history. This is a deliberate and visible limitation; there is no confirmed EUR intraday backfill from Navasan. The source's published free-plan update cadence is about two hours, while GoldBrain's development quota guard calls the source **no more than once every eight hours**. The UI now discloses both timings and does not claim live streaming. The 120-request/month free ceiling may constrain continuous three-person chart use; no paid plan was purchased.
